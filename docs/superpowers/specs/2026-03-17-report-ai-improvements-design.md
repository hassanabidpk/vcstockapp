# Improve Daily & Weekly Report AI Analysis

**Date:** 2026-03-17
**Status:** Approved
**Approach:** B — Enriched Data Context + Prompt Rewrite

## Problem

The AI analysis in Telegram reports is generic and surface-level:
- Market commentary doesn't connect index moves to the user's specific holdings
- Insights lack actionable, symbol-specific recommendations with price context
- The `topMovers` field is generated by the AI but never rendered in the formatter
- AI analysis is budget-constrained into leftover space after portfolio data

## Design

### 1. Enriched Data Context

Add context fields to each holding before sending data to the AI agent:

| Field | Type | Source | Purpose |
|---|---|---|---|
| `distanceFromEntry` | `number` (%) | Alias for existing `profitLossPercent` | Renamed in AI context for prompt clarity — makes the AI reference "entry price" rather than abstract P/L |

Note: `distanceFromEntry` is functionally equivalent to `profitLossPercent` (which is `(currentPrice - avgBuyPrice) / avgBuyPrice * 100`). It is intentionally aliased under a different name in the AI prompt context so the model naturally references "entry price" and "distance from buy" in its analysis. No new computation needed.

**Dropped: `priceTrend7d`** — Portfolio snapshots are portfolio-level aggregates (`totalValue`, `totalCost`, `totalPL`), not per-holding price history. Building per-holding 7-day trends would require additional API calls to price services for each symbol, which adds latency and complexity. The AI agent already has Google Search to look up recent price action when needed. Instead, we rely on `distanceFromEntry` + `changePercent` (today's move) + Google Search for momentum context.

**File:** `data-collector.service.ts`
- Add `distanceFromEntry` as an alias of `profitLossPercent` when building the AI context message

**File:** `types.ts`
- No changes to `CollectedHolding` (field already exists as `profitLossPercent`)

### 2. Prompt Restructure

**File:** `prompts.ts`

Replace the current output schema with a portfolio-aware structure.

**Current schema (daily):**
```json
{
  "marketOverview": "...",
  "topMovers": "...",
  "insights": "..."
}
```

**New schema (both daily and weekly):**
```json
{
  "marketOverview": "2-3 sentences on US indices + macro, connecting index moves to specific holdings in the portfolio. Mention SG/HK/crypto market moves when relevant to holdings.",
  "holdingActions": [
    {
      "symbol": "PLTR",
      "action": "hold",
      "reasoning": "62% above $18.50 entry but dropped 3 of last 5 days — hold but watch $48 support"
    }
  ],
  "risks": "1-2 sentences on the biggest risk to this portfolio right now",
  "outlook": "1-2 sentences on what to watch next (earnings, levels, catalysts)"
}
```

**Key changes:**
- `topMovers` removed — redundant with the data message that already shows movers
- `holdingActions` replaces `insights` — forces named symbols with a stance (hold/trim/accumulate/watch)
- `risks` added — portfolio-specific risk assessment
- `outlook` added — forward-looking, replaces generic insights
- `marketOverview` instruction requires connecting market moves to portfolio holdings
- Weekly no longer needs separate `sgMarket` / `cryptoMarket` fields — the enriched data and market overview instruction cover these when relevant to holdings

**Prompt rules additions:**
- "For each holding, you have `profitLossPercent` (% distance from buy price) and `changePercent` (today's move). Use these to ground your recommendations. Use Google Search to look up recent price action, support/resistance levels, or earnings dates when relevant."
- "In `holdingActions`, cover the top 3-5 most noteworthy holdings — biggest movers, most at-risk, or best opportunities. Do not list every holding."
- "Every action must reference the entry price or recent trend to justify the recommendation."

**Daily vs weekly prompt:** `getSystemPrompt()` still accepts `reportType` and branches. The output JSON schema is unified (same fields for both). The difference is in the instruction text: weekly adds "Include weekly performance context and compare to last week's snapshot data" to the base instruction. The separate `DAILY_OUTPUT_FORMAT` / `WEEKLY_OUTPUT_FORMAT` constants are merged into a single `OUTPUT_FORMAT` constant, with a small weekly addendum appended conditionally.

### 3. Message Layout

**File:** `report-formatter.service.ts`

Split the report into two Telegram messages:

**Message 1 — Portfolio Data (unchanged)**
Header, portfolio summaries, movers, FX rates. No AI content. Always clean and complete.

**Message 2 — AI Analysis (new, dedicated)**
Full 4096 chars available. No more budget-constraining.

Format:
```
🤖 AI ANALYSIS

📈 MARKET
{marketOverview — connecting index moves to portfolio}

⚡ ACTIONS
🟢 NVDA — Hold. 45% above $120 entry, momentum intact...
🟡 TSLA — Watch. Testing $180 support, 3 red days...
🔴 CRWV — Trim. 28% below entry, no catalyst...

⚠️ RISKS
{risks}

🔭 OUTLOOK
{outlook}
```

Action emoji mapping:
- `hold` → 🟢
- `accumulate` → 🔵
- `watch` → 🟡
- `trim` → 🔴

**File:** `types.ts`

Update `AnalysisResult`:
```typescript
interface HoldingAction {
  symbol: string;
  action: "hold" | "trim" | "accumulate" | "watch";
  reasoning: string;
}

interface AnalysisResult {
  marketOverview: string;
  holdingActions: HoldingAction[];
  risks: string;
  outlook: string;
}
```

### 4. Formatter Changes

- Remove `buildAI()` budget logic — AI section is no longer squeezed into leftover space
- New `buildAIMessage()` function formats the AI analysis as a standalone message
- `splitMessages()` is still applied to the data message independently (portfolios with many holdings could still exceed 4096 chars)
- `format()` builds data messages via `splitMessages(dataText)`, then appends the AI message. Returns all as `{ messages: [...dataMessages, aiMessage] }`
- When AI analysis is `null` (timeout/error), only the data message(s) are sent (same as current fallback)

### 5. Agent Parser Changes

**File:** `agent.ts`

Update `parseAnalysisResult()` to handle the new schema:
- Parse `holdingActions` array (with fallback to empty array)
- Parse `risks` and `outlook` fields
- Remove `sgMarket` / `cryptoMarket` parsing

## Files Changed

| File | Change |
|---|---|
| `services/reports/types.ts` | Add `HoldingAction` interface; update `AnalysisResult` (remove `topMovers`, `sgMarket`, `cryptoMarket`; add `holdingActions`, `risks`, `outlook`) |
| `services/reports/data-collector.service.ts` | No structural changes — `profitLossPercent` already exists on holdings. Prompt references it as "distance from entry" |
| `services/reports/ai-analyzer/prompts.ts` | Rewrite prompt with portfolio-aware output schema; merge daily/weekly format constants; add instruction to use Google Search for price action |

## Not Changing

- Cron schedule (daily weekdays 8 AM SGT, weekly Saturday 6 PM SGT)
- Telegram delivery mechanism
- Google ADK agent setup and Google Search tool
- Portfolio data message format
- Data collection for portfolio summaries (only enriching holdings)
